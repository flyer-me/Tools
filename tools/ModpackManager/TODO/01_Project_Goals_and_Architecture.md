# ModpackManager 架构文档 - 第一部分：项目目标与总体架构

## 1. 项目目标与背景

### 1.1 背景概述
ModpackManager 是一款面向 Illusion 系列游戏（如 Honey Select 2、AI Shoujo 等）的现代化 Mod 管理工具。此类游戏通常拥有极其庞大的社区 Mod 生态，主要以 `.zipmod` 格式存在。由于缺乏统一管理，玩家在日常面临着 Mod 数量庞大、重复安装、依赖缺失以及手动安装繁琐等痛点。

本系统旨在提供一套轻量、高效的技术底座，帮助玩家实现 Mod 的智能化管理。

### 1.2 核心业务目标
* **Mod 索引与扫描**：快速并发扫描游戏目录下的所有 `.zipmod` 文件，提取元数据。
* **Metadata 仓储**：本地持久化缓存 Mod 信息，支持秒级启动与多维检索。
* **智能去重与冲突检测**：通过哈希与文件路径比对，精准识别重复 Mod 及文件冲突。
* **依赖解析（Dependency Resolver）**：基于有向无环图（DAG）自动分析 Mod 间的依赖关系。
* **自动补全与网络分发**：与远程社区仓库（Repository）同步，自动识别并下载缺失的依赖。
* **隔离集成**：复用 `KKManager Core` 的解析能力，同时保持架构独立性。

### 1.3 质量属性目标（ADD 聚焦）
* **简单性（Simplicity / KISS）**：拒绝为了解耦而解耦。不引入复杂的 DDD（领域驱动设计）聚合根、CQRS 或过度抽象的仓储层，优先采用直接的方法调用和清晰的分层。
* **高可维护性（Maintainability）**：代码结构单一直观，核心业务逻辑内聚。保证在 1~2 人维护的情况下，新功能扩展或外部依赖变更不会导致系统大范围重构。
* **性能与响应力（Performance & Responsiveness）**：
  * **I/O 优化**：面对海量小文件和超大压缩包，全面采用 .NET 异步流（`IAsyncEnumerable`）和并行 I/O 调度，确保扫描期间 WPF 界面拥有 60 FPS 级别的丝滑响应。
  * **内存控制**：严禁一次性将数万个解压后的完整元数据加载至内存，采用流式处理和轻量索引缓存。

### 2.2 层级职责定义

1. **ModpackManager.UI (展现层)**
   * **职责**：负责所有的 UI 渲染、用户交互、多语言本地化、异步加载动画展示。
   * **技术**：WPF, CommunityToolkit.Mvvm, 视图模型直接调用 `Core` 层的应用服务。
2. **ModpackManager.Core (核心业务层)**
   * **职责**：系统核心。包含去重算法、冲突判定、拓扑依赖解析引擎、下载调度器。该层为**纯净的 .NET 库**，严禁引用WPF 或第三方组件。
3. **ModpackManager.Adapter.KKManager (适配器/防腐层)**
   * **职责**：作为与 `KKManager Core` 交互的唯一通道。负责调用外部解析库并将其混杂的数据结构转换为 `Core` 层定义的清净模型（`ModMetadata`）。
4. **ModpackManager.Storage (数据存储层)**
   * **职责**：负责配置信息、本地 Mod 索引、远程仓库缓存的持久化与高效检索。
